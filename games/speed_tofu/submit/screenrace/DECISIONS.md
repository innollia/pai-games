## v12 배달 규칙 (2026-10-31, 마감 날)
- 왜: SIMILAR.md 2절에서 SpeedRunners와 "표절 위험 높음"이 나왔다. 선두 카메라 + 화면 밖으로 밀어내 탈락 + 마지막 생존자 승리라는 승패 구조가 그대로 같았다. 사용자가 A(배달로 이기기)와 B(화면 테두리 = 짐 벽) 둘 다 승인했다.
- A. 이기는 법을 "살아남기"에서 "배달 수"로 바꿨다.
  - 코스마다 빨간 종이 우체통 7~9개(평평한 맨땅, 점프대·얼음·다리 판·선로·문·장치 옆은 피함, 서로 12 이상 떨어짐, 모자라면 6개까지 채움). 연습 마당은 연습용 1개.
  - 우체통 1.3 안에서 짐 버튼 = 배달(짐 -1, 배달 +1, 깃발이 서서 배달한 사람 색이 되고 몸통이 잿빛 남색, 지붕에 짐이 꽂힘, DELIVERED 도장 + 초록 +1). 우체통 하나에 짐 하나, 먼저 넣은 사람. 배달에는 대시가 없다. 우체통 밖에서 짐 버튼 = 예전처럼 던지고 대시.
  - 왼쪽 끝에 밀리면 탈락이 아니라 "반송": 짐 하나를 왼쪽 끝 조금 안쪽 땅에 흘리고(남이 주울 수 있고, 본인은 2.5초 못 주움), 0.6초 뒤 왼쪽 끝에서 다시 들어온다(1초 무적 깜빡임, 그동안은 끝이 부드러운 벽). 짐이 없어도 다시 들어온다. 구덩이 추락·안개 길 잃기·기차도 같은 반송(기차는 빈손이면 튕기기만). 찢긴 종이 끝 + 슬로모션 순간은 그대로 남겼다(이제 뜻은 "반송, 짐 -1").
  - 판 끝: 누가 처음 결승에 닿으면 3초 "마감 임박(LAST CALL)", 그 뒤 판이 끝난다. 이긴 사람 = 이번 판 배달 최다(같으면 먼저 도착, 그다음 앞선 쪽). 240초가 지나도 아무도 안 닿으면 마감을 시작한다. 결승 뒤 26에서 멈춘다.
  - 짐: 판마다 4개(+특전 끈)를 새로 받는다(LOAD0 3 → 4). 줍는 짐은 그대로.
  - 기록 파일을 user://screenrace_v12.cfg 로 새로 연다: 옛 규칙의 '최고 배달'이 섞이지 않고, 돌아온 사람도 바뀐 규칙 연습을 한 번 본다(언어 설정은 영어로 돌아간다).
  - 기록·메달: records "delivered" = 진짜 넣은 짐 수의 합(우체통마다 +1, 점수 +20). 금 = 2판 안에 이기고 그 코스에서 4개 이상 배달, 은 = 3판 안, 동 = 통과.
  - 전략의 중심: 1등은 화면이 앞으로 쏠려 앞의 우체통이 늦게 보이고 빨라서 지나친다. 뒤에 붙으면 보고 멈춰 넣는다. 막대 아래 작은 우체통 표(빨강 = 빈 곳, 골판지 = 찬 곳)로 뒤에서 계획한다. 우체통은 배달부만큼 크게(1.25배) 그렸다.
  - 경쟁자: 앞 6 안에 빈 우체통이 보이면 한 번 정한다. 넣을 확률 = 0.55 + 2 x (기술 - 0.93) (대략 0.5~0.75). 1등이면 -0.1, 빠르면(최고 속도 70% 넘으면) 최대 -0.35 더, 화면 가운데보다 반폭의 35% 넘게 앞서 있으면 -0.25, 정전 -0.25, 등불 모드에서 빛 밖 우체통은 0.12. 넣기로 하면 다가가며 속도를 줄이고 0.8 x 1.3 안에서 짐 버튼. 배달 노리는 중에는 짐을 안 던지고, 끝에 몰렸을 때 던지는 확률도 0.25 → 0.12로 낮췄다.
  - 모드: 과속은 그대로(짐 2개 이하 천장 가속·벽 반동 — 배달하면 가벼워져 빨라지고, 빨라지면 우체통을 지나친다). 밤 등불은 우체통이 안개 막 뒤라 빛 안에서만 보인다.
  - 연습: 달리기 → 점프 → 우체통 앞 짐 = 배달 → 다른 곳 짐 = 던지고 대시 → 왼쪽 끝 = 짐 -1 → "배달 많이 한 사람이 이긴다!"
  - HUD: 막대 핀 안 숫자 = 이번 판 배달 수(내 핀이 크다, 혼자 배달 1등이면 금 테). 영수증 큰 숫자 = 배달한 짐. 모드 카드 한 줄과 길잡이 글에서 "목숨·실격·살아남기" 말을 뺐다. 새 패널은 없다.
- B. 화면 테두리를 짐으로 만들었다.
  - 화면 양옆 34px = 짐 벽(골판지 바탕 위에 세운 소포 벽돌, 아래부터 쌓임). 벽돌 하나 = 지금 누가 든 짐 하나, 테이프 색 = 주인(왼쪽 벽: 나 파랑 아래 + 빨강 위, 오른쪽 벽: 민트 아래 + 노랑 위). 벽돌 높이 60, 간격 5.
  - 카메라는 화면 폭에서 벽 둘을 뺀 만큼이 정확히 2 x hwv가 되게 넓게 찍는다(_wall_k). 그래서 왼쪽 벽 안쪽 면 = 진짜 떨어지는 끝이고, 찢긴 종이 띠가 그 면에 붙어 있다. 오른쪽 벽 안쪽은 크림 띠.
  - 짐이 줄면(배달·던지기·반송) 벽돌이 안쪽으로 톡 튀어 나가며 흐려지고 작은 소리, 화면 폭(hwv)도 같이 좁아진다. 주우면 배달부에게서 벽으로 날아 들어와 톡 부푼다. Control 하나의 _draw, 미리 만든 10개 조각만 돌려 쓴다.

## 경제 실험판 (2026-10-31)
- 사용자 지시: "들고 있는 박스 수 2배, 다른 수치도 1/2배·2배 버전 전부 게임 목록에". 경제를 폰 평가로 조율하는 단계.
- screenrace.gd에 배수표 `tune`(기본 비어 있음 = 원래 게임)과 tn(k)를 두고, 실험판 `g/screenrace_t_<키>_<x2|x05>.gd`(18개)는 tune만 바꾼다. SPEED 두부 목록 "⚖ 화면 밖 경주 실험: …"으로 들어가며 평가가 판마다 따로 쌓인다. 화면 오른쪽 아래에 "TEST 키 x배수"가 보인다.
- 키: load(출발·최대 짐 수), weight(짐 하나당 느려짐·점프 감소), dash(대시 속도), mail(코스당 우체통 수), mb_r(배달 범위), ai(상대 배달 확률), view(화면 폭), last(마감 시간), speed(달리기 최고 속도).
- 단독판(잼 제출본)은 원래 수치 그대로. 결과를 보고 고른 값을 원본 상수에 반영한다.
